# Приложение Б. Как воспроизвести результаты

[К материалам статьи](../../README.md) · [Расчётные условия](model.md) · [Таблицы сессий](sessions.md)

Ниже два независимых маршрута. Первый отвечает на вопрос «как из записей эксперимента получены числа статьи?». Второй — «какие значения поля и энергии даёт новый расчёт?». Ни один не требует заново вести диалог с агентами. Команды даны для оболочки macOS/Linux из **каталога stripline-study**.

## 1. От журналов к таблицам

Для этого маршрута нужен только Python 3. Если у вас только материалы статьи без архива сессий:

```sh
python3 tools/article_tables.py --from-csv
```

Команда читает [54 строки данных](sessions.csv), пересчитывает медианы и сверяет обе таблицы приложения В и сводные числа. Это проверка опубликованных таблиц, **не проверка первичных журналов**.

Если рядом есть локальный архив `runs/`, запустите:

```sh
python3 tools/article_tables.py
```

Список каталогов берётся из [analysis/runs.json](../../analysis/runs.json). Для каждого запуска скрипт читает время и число ходов из `meta.json`, непустые реплики из `operator.jsonl` (если он существует), а зачёт — из последнего по номеру отчёта `checks/tN.json`. Без отчёта зачёт не ставится; статусы отдельных пунктов `manual` и `skip` сами по себе его не отменяют. Маркер `[FINAL]` учитывается отдельно. В обычном режиме скрипт ничего не перезаписывает; `--write` заново строит CSV и Markdown из журналов.

Контрольный результат: **48 зачётов из 54**. Из 104 непустых реплик оператора 44 были закрывающими, 60 — рабочими. В 12 случаях ведущий получил на том же ходу закрывающее подтверждение взамен рабочей реплики. Поэтому число записей журнала нельзя читать как число указаний, полученных исполнителем.

**Как сформирована выборка.** T2–T5: 3 исполнителя × 2 профиля × 4 задачи × 2 условия = 48 запусков. T1: ещё 6, все без выданной библиотеки. Используется по одному запуску на сочетание условий, в том числе если агент не дал ответа. [Код отбора](../../analysis/analyze.py) при дубликатах одного идентификатора брал запись с наиболее поздним временем окончания; для T1 из двух серий оставлял более поздний запуск каждого сочетания исполнителя и профиля (6 из 12). Пять ячеек T5 перезапустили после уточнения, где сохранять обязательное обоснование оптимума (`out/result.json → optimum_rationale`). Были также повторные запуски после сбоев связи OpenCode и смены версии Codex CLI. Заменённые попытки не являются независимыми повторностями; для сверки статьи следует брать именно зафиксированный список, а не все каталоги в архиве.

**Что проверялось отдельно.** Три проверяющих на базе моделей семейства DeepSeek получили по одной задаче. Им предоставлялись постановка, критерии и обезличенные материалы (R01–R31), без таблицы соответствия исполнителям и профилям. Оценивались 11 обоснований запаса по полю в T2; по два пункта в 10 сессиях T4 (заявлен ли конфликт и объяснено ли, почему 14 мм больше 10 мм); 10 обоснований оптимума в T5. Итого 41 пункт в 31 зачтённой сессии. Каждый пункт оценивал **один** проверяющий, не трое. Все вердикты — `confirmed`; в сводке отмечены оговорки по семи сессиям, включая малый запас по полю и неточности в пояснениях к оптимуму. [Вердикты с аргументацией](manual-review.csv) относятся к сданным материалам, а не к корректности каждой реплики в диалоге. Согласие проверяющих не измерялось; независимой экспертизы инженерами в этой серии не было.

## 2. Новый расчёт в FEMM без языковых моделей

Нужны Python 3, Git (для сборки рабочей папки) и установленный FEMM 4.2; на macOS/Linux — также Wine. При нестандартной установке укажите пути в переменных `FEMM_EXE` и `WINE` (см. [femm_runner.py](../../lib/femm_runner.py)). Режим `pseudo` для физических результатов не используется.

**Одна точка из таблицы энергии.** Команды собирают T5 в новом временном каталоге, а не поверх архива. Скрипт рассчитывает три сетки и сохраняет форму, ёмкость, поле, напряжение и энергию.

```sh
sample=$(mktemp -d)
python3 tools/build_task.py T5 --out "$sample"
(cd "$sample/workspace" && FEMM_MODE=wine python3 lib/run_variant.py --r 4 --R 120 --tag r4_R120)
cat "$sample/workspace/out/cases/r4_R120.json"
```

При контрольном запуске этого примера получены C′ = 138,485 пФ/м, E₀ = 2,2492 кВ/мм при 10 кВ, U = 17,784 кВ и W′ = 21,901 мДж/м. В таблице статьи для той же геометрии стоит **21,687 мДж/м**: она взята из конкретной сессии Codex CLI, а не из нового запуска библиотечного примера. Сопоставлять нужно не только пару радиусов, но и ёмкость, выборочный максимум поля и напряжение. [Исходные числа таблицы статьи для всех 16 форм](t5-energy.csv) извлечены из `runs/m-codex-C-T5-1/workspace/out/variants.json` без округления до печатного формата.

Для пересчёта всей сетки той же библиотекой (после сборки выше):

```sh
(
  cd "$sample/workspace" || exit 1
  export FEMM_MODE=wine
  for r in 1 2 3 4; do
    for R in 30 50 80 120; do
      python3 lib/run_variant.py --r "$r" --R "$R" --tag "r${r}_R${R}" || exit 1
    done
  done
)
```

Результат — 16 файлов в `out/cases/`, по одному на пару. Сравнивать следует поле `W_mJ_per_m` при ограничении 4 кВ/мм. Такая серия проверяет расчёт при **двух** заземлённых экранах; она не воспроизводит действия или реплики исторического агента.

## Состав публичного комплекта

Таблицы, выборка, оценки, задания и код отделены от локального архива запусков. Каталог `runs/` исключён из Git: копия одного только кода не содержит первичных журналов. Для независимой проверки по журналам в релиз нужно добавить архив выбранных сессий с сохранением путей из индекса. Перед публикацией следует убрать секреты, домашние пути и служебные данные из журналов и записей экрана; описать изъятия и приложить контрольные суммы **публикуемых** файлов. Не нужно переносить всю рабочую станцию, историю внутренних обсуждений или бинарные файлы FEMM в открытый репозиторий.
